# 프로젝트 문서

이 디렉터리는 코드만으로 파악하기 어려운 현재 구조, 중요한 결정의 이유, 반복 가능한 문제 해결법을 기록합니다.

## 문서 지도

| 궁금한 점 | 문서 | 기록 기준 |
| --- | --- | --- |
| 시스템은 어떻게 구성되고 동작하는가? | [`architecture/`](architecture/) | 현재 구조, 모듈 책임, 주요 런타임 흐름 |
| 왜 이 방식을 선택했는가? | [`adr/`](adr/) | 대안이 있었고 장기 영향이 있는 결정 |
| 같은 문제를 어떻게 해결하는가? | [`troubleshooting/`](troubleshooting/) | 재발 가능하고 검색하기 어려운 장애 |

## 작성 원칙

- 문서는 한국어를 기본으로 하되 기술 용어와 코드 식별자는 원문을 유지합니다.
- 코드에서 바로 알 수 있는 정보보다 맥락, 경계, 결정 이유를 기록합니다.
- 현재 상태와 미래 계획을 구분하며, 구현되지 않은 내용을 현재 사실처럼 쓰지 않습니다.
- 한 문서는 한 질문에 답하고, 세부 내용은 코드나 관련 문서로 연결합니다.
- 문서가 필요하지 않은 PR에는 문서를 억지로 추가하지 않습니다.

## PR에서 판단하기

1. 시스템 구조나 주요 흐름의 이해가 달라지는가? → Architecture를 갱신합니다.
2. 여러 대안 중 장기적으로 영향을 주는 결정을 했는가? → ADR을 추가합니다.
3. 재발 가능하고 원인 파악이 어려운 문제를 해결했는가? → Troubleshooting을 추가합니다.
4. 실행 방법이나 요구 환경이 달라졌는가? → 루트 README를 갱신합니다.

새 문서는 [`templates/`](templates/)의 템플릿을 사용합니다. 최종 수정일은 문서에 중복 기록하지 않고 Git 이력으로 확인합니다.
